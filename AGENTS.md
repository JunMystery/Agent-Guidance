# MANDATORY AGENT EXECUTION PROTOCOL

> [!IMPORTANT] **Precedence**: 1. User Main Rules (`AGENTS.md`, `RULES.md`, `<user_rules>`) > 2. Runtime Gates (`workflow_gate`, `guidance(verify)`) > 3. MCP Micro-Rules (advisory).

This repository uses the `agent-guidance` MCP Server. Route code search and reads through it.

1. **Turn 1 Init & Skills**: Call `task_pipeline(task, project_path, phase="plan")` FIRST (bundles skill discovery; skip redundant `guidance(search)`). Exemptions: `is_minor=true` fast-path; slash-only and Q&A bypass skill proposals (`/<cmd>` stripped); mentioned skills rank first as `(Recommended)`; `/generative_ui` forbids `ask_question` (render HTML artifact `UserFacing: true` + `<agent-embed>`). When skills are proposed, ask via `ask_question(..., is_multi_select=true)` in user's language with full diacritics (`"[(Recommended) ]{name} - {short_desc}"`, `<= 50 chars`) before `select_skills(..., user_confirmed=true)` or inspecting code.
2. **Search & Clustered Read**: NEVER use native IDE search/read tools (`view_file`, `grep_search`, `find_by_name`, `list_dir`, etc.) or shell content reads (`Get-Content`, `cat`, `type`, `head`, `tail`, `sed`, `awk`, scripts) on codebase files. Use `project_context(operation="search" | "graph_rag" | "navigate" | "read" | "symbols")` (300-line read cap for token budget); reserve `run_command` for builds, tests, tools, and git. Batch reads with `relative_paths=[...]` and pass `authorize=true` when reading to edit.
3. **Plan & Approval**: Complete `/grill-me` `ask_question` turns BEFORE writing `implementation_plan.md` (never in the same turn). `ask_question` choices are design inputs, NOT plan approval—present `implementation_plan.md` (`RequestFeedback: true`) and STOP until explicit approval (`Proceed`, `ok`, `approved`, `triển khai`). `workflow_gate(action="approve_plan", user_confirmed=true)` auto-authorizes plan files + `deferred_authorized_paths`.
4. **Edit Gate, Domain Cohesion & Quality (300 LOC Soft Limit)**: Batch-authorize known files upfront via `workflow_gate(action="authorize_edit", project_path, relative_paths=[...], risk_level="LOW", justification, architecture_pattern="Auto")` (single `relative_path` for ad-hoc files only). Treat 300 LOC as a soft warning, NOT a hard cap (exempt: docs, configs, data, assets, tests)—above 300 LOC, ask if the file mixes unrelated responsibilities and keep cohesive files intact. Prioritize focused functions (target 15-40 LOC; warn > 60 LOC, cyclomatic > 10, cognitive > 15, nesting > 4), group files by domain/feature to localize edits, avoid cross-domain `*utils`/`*helpers` bags, and run static linters (`clippy`, `eslint`, `ruff`, `golangci-lint`).
5. **DRY & Reuse**: Search `shared/`/`utils/`/`common/`/`helpers/` via `project_context` first; reuse functions (>85% match) instead of duplicating logic.
6. **Verify, Test Isolation & Async**: Run tests and static linters via `guidance(operation="verify", verification_command, expected_output_keyword)`. Isolate tests from live user/prod data (temp dir / in-memory DB), prefer `patch.object`/DI over string-path mocks with call assertions, and guard production config/backup writes against partial/empty overwrites. Stop calling tools after launching background tasks and wait for wakeup.
