## When to use me
- At the start of every task, repository lookup, or phase transition (`plan -> build -> test -> review`).

## Execution Protocol (`agent-guidance` MCP)
1. **Init & Skills**: Call `task_pipeline(task, project_path, phase="plan")` FIRST (bundles skill discovery; skip `guidance(search)`). Exemptions: `is_minor=true` fast-path; slash-only and Q&A bypass skill proposals (`/<cmd>` stripped); mentioned skills rank first as `(Recommended)`; `/generative_ui` forbids `ask_question` (render HTML artifact `UserFacing: true` + `<agent-embed>`). Confirm proposed skills via `ask_question(..., is_multi_select=true)` in user's language (`"[(Recommended) ]{name} - {short_desc}"`, `<= 50 chars`) before `select_skills(..., user_confirmed=true)` or inspecting code.
2. **Search & Bounded Read**: Use `project_context(operation="search" | "graph_rag" | "navigate" | "read" | "symbols")` (300-line cap); batch `relative_paths=[...]` and pass `authorize=true` when reading to edit. Never use native IDE/shell read/search tools when MCP is available; **MCP-unavailable fallback**: only when `agent-guidance` MCP tools are unavailable or disallowed in a subagent/swarm worker context, fall back to bounded read-only native reads (`read_file` with explicit line bounds) on assigned files ONLY (never bypass MCP when it IS available).
3. **Plan & Approval**: Complete `/grill-me` `ask_question` turns BEFORE writing `implementation_plan.md` (never in the same turn). `ask_question` choices are design inputs, NOT plan approval—present `implementation_plan.md` (`RequestFeedback: true`) and STOP until explicit approval (`Proceed`, `ok`, `approved`, `triển khai`); `workflow_gate(action="approve_plan", user_confirmed=true)` auto-authorizes plan files + `deferred_authorized_paths`.
4. **Edit Gate, DRY & Quality**: Batch-authorize via `workflow_gate(action="authorize_edit", relative_paths=[...])` or `approve_plan(user_confirmed=true)`. Search `shared/`/`utils/`/`common/`/`helpers/` first (DRY). Treat 300 LOC as a soft cohesion warning (exempt: docs, configs, data, assets, tests); prioritize small functions (15-40 LOC; warn > 60 LOC, cyclomatic > 10, cognitive > 15, nesting > 4) and domain-grouped files.
5. **Verify, Test Isolation & Async**: Register the verification contract & safety check via `guidance(operation="verify", verification_command=..., expected_output_keyword=...)` (does not spawn shells), run tests/linters (`clippy`, `eslint`, `ruff`, `golangci-lint`) via `run_command`, and pass `workflow_gate(action="pass_verification", verification_output=...)` on stage transition. Isolate tests (temp dir / in-memory DB), prefer `patch.object`/DI with call assertions, guard production config/backup writes, and wait for background-task wakeup.
